**How an enumerated knob works, end to end:**
1. The knob is a `$type: "string"` with `$extensions: {"com.jarodtaylor.enum": ["rules","none"]}`.
2. `derive.ts` checks the value against `DECORATIONS` and outputs it as `knob.decoration`.
3. Generated `src/styles/tokens.css` chains it: `--knob-decoration: rules;` → `--decoration: var(--knob-decoration);` → `--section-decoration: var(--decoration);`, inside `:root, [data-brand="default"]` and `[data-brand="alt"]` blocks in `@layer tokens`.
4. The only consumer is `src/components/SectionShell/SectionShell.css`:
   ```css
   @container style(--section-decoration: rules) {
     .section__title { border-block-end: var(--section-rule-width) solid var(--_border); ... }
   }
   ```
   A comment there notes that style queries only match descendants, which is why the rule sits on the title rather than the section.

## 2. scripts/derive.ts (320 lines, pure, no imports)

`derive(knobs)` validates the knobs and returns primitives:
- **`color.neutral` / `color.accent`:** 12-step OKLCH ramps (0, 50 … 950). Lightness is fixed per step (0.995 down to 0.22). Chroma is the knob value times a taper, then reduced until it fits sRGB. Each color also gets a `hex` fallback.
- **`font.size`:** steps xs through 5xl, computed as base × ratio^(−2…6).
- **`font.line-height`:** tight 1.1, snug 1.3, normal 1.55 (fixed).
- **`font.family` / `font.weight`:** copied straight from the knobs.
- **`size.space`:** steps 1–10, computed as base × multiplier (0.25…8) × density.
- **`size.radius`:** sm ×0.5, md ×1, lg ×2, full 9999px.
- **`size.border`:** thin ×1, thick ×2.
- **`knob.decoration`.**

**Fonts:** only family arrays and a body/display weight exist. There are no `wdth` or other axes, no font-variation tokens, no `@font-face`, and no font loading at all. I searched src, scripts, tokens, astro.config and package.json and found nothing; the brands use system and local font stacks. Per-brand font loading is planned but not built. `docs/PLAN.md:96-97` says the default brand's fonts should be self-hosted, subset, preloaded and metric-matched, and other brands' fonts should load "only when that brand is activated". The markup-invariance test already excludes those future lazily injected `&lt;link&gt;`s.

## 4. Tests and lint

**`tests/markup-invariance.e2e.ts`:** for every built page, it loads the page under each brand via `?brand=` and snapshots `&lt;body&gt;` outerHTML. It then sets `dataset.brand` on the client for each other brand, waits two animation frames and snapshots again.
- The HTML must be identical.
- A computed-style string must differ, so the test can't pass if switching silently did nothing. It compares color, background-color, font-family, font-size, font-weight, padding, border and border-radius across all elements.
- It strips Remix UI state attributes (`open`, `hidden`, `aria-expanded`, `data-state`, …) under `[data-remix-ui]`.
- It skips if there are fewer than two brands.
- `tests/site.ts` supplies `brands` and `builtPages`. `a11y.e2e.ts` also exists.

**Stylelint (`scripts/stylelint-plugin-tokens.ts` plus `stylelint.config.js`):**
- **`tokens/tier-vars`:**
  - Every `var(--x)` and every property named in a style query must be a semantic or component token, or a private `--_` prop. Primitives (`--color-*`, `--size-*`, `--font-*`, `--knob-*`) and unknown names are rejected.
  - Declaring any non-`--_` custom property is forbidden.
  - A `--_` prop's value must be var() references only.
  - The allowed list is read live from the token JSON.
- **`tokens/no-brand-keys`:** no selector or at-rule condition may contain `data-brand` or `--brand`.
- **Config rules:**
  - No hex colors, named colors, or color functions (rgb…oklch, color-mix, light-dark).
  - Units are limited to `%` and `fr`.
  - `font*`, `line-height` and `letter-spacing` values must be a single `var(--…)`.
  - Every disable comment needs a reason.
- `tokens.css` and `reset.css` are not linted.
