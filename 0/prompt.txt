## 3. JS

**Backstage `hero.js`** (7.2 KB)
- Builds the bleed lines: each guide is extended 5000 units from both ends into `.mono-bleed`.
- Clones `.mono-line` as `.mono-pen`. CSS animates the pen as a 0.03 dash lapping the outline every `--pen-lap` 16s.
- Writes live readouts: the computed font sizes and families go into `data-spec` / `data-readout`.
- `timeVertices()` samples both outline paths at 301 points and gives each vertex circle an `--at` delay so it pops as the pen passes.
- A state machine sets `html[data-peek-state]` to `arm`, `on` or `leaving`, or removes it. The Peek toggle and Escape drive it.
- Intro: the inline head script sets `.js`, `.intro` and `data-peek-state=arm`, guarded by sessionStorage `jt-intro`, `?intro` and no-preference reduced motion, with a 4s failsafe. The JS waits for `fonts.ready` (capped at 700ms), runs show, waits `--peek-settled` + `--peek-hold`, then hides. Any keydown, pointerdown, wheel, touchmove or scroll triggers `settle()`, which applies a no-transition frame via `.settling`. It also runs the phone menu.
- Reduced motion: the intro is never armed, all transitions and animations are disabled, and the pen is `display:none`. Peek still works, as an instant cut.

**Blocks `hero.js`** (1.2 KB)
- Exits unless `.intro` is set. Sets sessionStorage `jt-r6-blocks`.
- Skip (keydown, pointerdown, wheel, touchstart) calls `.finish()` on every finite animation. On `load` it waits for all of them to finish, then removes `intro` and `building`.
- All choreography lives in CSS (`.building`):
  - The rail draws out from the joint through the `rail-reveal` mask.
  - Arrows draw then retract.
  - The parts travel linearly from ±(123.36, 213.67) along the 60° rail and both arrive at `--t-click` 1340ms.
  - Faces stay paper line-drawings on the field colour until the click, then a `step-end` switch fills them with colour.
  - On the click the assembly scales to 1.022, three click strokes appear, and the rail opacity eases from .8 to .34.
  - Text rises in a stagger; the name is never animated.
- Hover (when hover is available and motion is allowed): the parts pull apart by (10.28, 17.8).
- Reduced motion: the head script never adds `.intro`, the status pulse `::after` is gated off, and the hover pull is gated off.

**Clean `field.js`** (4.9 KB)
- A canvas 2D lattice: side `s = W/14`, row height `r = s·√3/2`. Each vertex draws edges at 0°, 60° and 120°.
- Strokes are grouped by alpha quantised to 0.02. The base pass uses `--field-line` at .05 + .2 glow. Inside `clip(mark)` it uses `--field-mark` at .22 + .45 glow, then strokes the outline at .3.
- A ring of light expands from the mark centre every 9000ms, throttled to 33ms per frame.
- ResizeObserver (80ms debounce), IntersectionObserver and visibilitychange pause it.
- No intro and no session handling.
- Reduced motion: draws one still frame with no ring and listens for media-query changes. CSS kills the transitions and the breathe animation.

## 4. Monogram geometry

**The outline is shared.** All three use the same two path strings from `src/assets/jt-logo-icon.svg` (`M286.22 164.31h.08l-41.1-71.17…` and `m230.41 73.72 26.52.12…`) on base viewBox `0 0 575.65 502.31`. The header mark is the same in all three, though Backstage references a `&lt;symbol&gt;` while the other two inline the paths.

**Each figure frames it differently:**
- **Backstage** pads by 40 on every side (`-40 -40 655.65 582.31`). Its guides follow the outline's own edge lines (y = 73.6, 93.2, 164.3…), not the 14-division lattice.
- **Blocks** redraws the outline as absolute-coordinate front faces. It is the same shape, except the J's front face starts at `M286.3 164.31`, folding in the `h.08` step. It adds extruded side faces offset by (+20.56, −35.61), which is length 41.12 at 60°, and its viewBox `-10 -45.61 616.21 557.92` includes that depth. Its `pattern#lattice` is 41.12 × 71.22 (two rows of 35.61), which is exactly Clean's lattice: 575.65/14 = 41.12, and 41.12·√3/2 = 35.61.
- **Clean** draws the same lattice on canvas, scaled to page size by W/575.65.

So Blocks and Clean share the lattice, and Backstage uses outline-edge guides. One caveat: the outline is not exactly on the 14-division lattice. For example, 164.31/35.61 = 4.61 rows, so both comments slightly overstate the fit.

## 5. Differences a custom-property value cannot express

1. **Figure renderer:** SVG construction drawing (Backstage), SVG extruded assembly with lattice pattern and rail (Blocks), or a full-viewport canvas (Clean). These are different elements and a different JS module each, so this needs an enumerated `figure` knob.
2. **Figure placement model:** a grid item in columns 6/-1 (Backstage), absolutely positioned at 54vw on the right (Blocks), or a canvas behind the whole first viewport at `z-index:-1` positioned by JS (Clean). On phones: behind the name at .3 opacity, a block above the name, or a canvas bleeding off the top.
3. **Intro system:** a Peek state machine with an intro-plus-replay toggle (Backstage), a one-shot CSS build that skips via `finish()` (Blocks), or none (Clean). The sessionStorage keys differ, and only Backstage has the `[data-skip-intro]` button and the 4s failsafe.
4. **Peek-only DOM** in Backstage: the `.cols` grid lines, `.dims`, `dl.spec`, the `data-peek` / `data-spec` / `data-build` attributes, the redline `::before`/`::after` boxes, and the Peek toggle with `symbol#reg`.
5. **Resting animation:** the pen lap (Backstage), the hover pull-apart of the parts (Blocks), or the expanding light ring (Clean).
6. **Phone nav mechanism:** a JS aria-expanded button with an ≡ drawn in CSS, a `popover` with an SVG icon, or a wrapped second row with no toggle.
7. **Header structure:** Clean nests the info strip inside an absolute `header.site &gt; .bar`. The others use a sibling info strip in a stage grid with rows `auto auto 1fr`. Backstage also centres the nav absolutely at 64rem and up.
8. **Hero text grouping:** stacked bottom-left in one column (Backstage, Blocks), or the name on its own row above a ruled 12-column details row with right-aligned socials (Clean). This needs a wrapper element and grid-column spans per breakpoint.
9. **Name markup:** Backstage needs two spans to force the 2-line break on phones, plus `white-space: nowrap`. Clean relies on `text-wrap: balance` with a phone-only size override.
10. **Tagline accent:** a partial span (`.hl` or `em` around "behind the work.") versus the whole tagline in accent. This is expressible only if the span always exists and its colour is a token, so the markup should always carry it.
11. **Cue:** none, icon-only shown at 60rem and up, or a labelled "Selected work" link. Needs presence and variant knobs.
12. **Status dot:** a real span (Blocks, scale-pulse `::after`) versus `::before` with a box-shadow breathe. This is unifiable, but the animation keyframes differ, so it needs a knob or one shared choice.
13. **Text transform:** Backstage sets nav, talk and Peek labels uppercase with +.08em tracking and the mono sentence case only for info and socials. The others never uppercase. `text-transform` can take a token value, but the per-element split (mono vs text face per role) needs role-level font tokens.
14. **Font axes mechanism:** `font-stretch` (Backstage) versus `font-variation-settings` (Blocks). Clean has no axes. Both can be tokens, but a token set must define both, with defaults `normal` and `normal`.
15. **Font loading:** Google `@import` (Backstage, Clean) versus self-hosted `@font-face` with preload (Blocks). This is a different `&lt;head&gt;` and `fonts.css` per brand.
16. **Talk button shape:** pill filled with accent (Backstage), outlined with 0.375rem radius (Blocks), or square outlined (Clean). Mostly tokenisable (radius, fill and border colours), but the hover inversion target differs.
17. **Below-fold `.next`:** inside versus outside `main`, paper versus pine-deep background, with or without an `h2`.
18. **Blocks figure semantics:** `role="img"` with a `&lt;title&gt;`, versus `aria-hidden` (Backstage) or a decorative canvas (Clean).
19. **Breakpoint values:** 48/64rem, 47.99/60rem, and 720/1100/1800px. Media queries cannot read custom properties, so one breakpoint set has to be chosen, or the per-brand layout handled with container queries and class switches.</result>
